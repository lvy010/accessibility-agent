# 发布与验收

## 交付范围

交付源码、锁定依赖、自动测试、中文说明、CI 定义和 VSIX 包。不发布 Marketplace，不部署后端，不提交或推送代码。

## 自动质量门禁

- 类型检查、单元测试、构建全部成功。
- 真实浏览器检测发现无名按钮，修复后该规则不再失败；请求策略测试确认 POST 和未授权来源被阻止。
- Extension Host 在最低版本及目标稳定版验证激活、命令、真实编辑、保存、撤销、冲突拒绝。
- 使用测试替身覆盖模型流式响应、协议错误、输出限制、上下文预算、权限与额度错误、断流、取消和无模型；不将替身测试视为真实 AI 授权验收。
- 真实项目任务验证退出码 0、非零、超时、取消与调用前取消，支持目标文件夹任务及经确认的工作区级任务。
- 运行时依赖安全审计没有未处理的高危漏洞；保留锁文件以便复现。
- VSIX 包中包含主入口、侧栏资源、Playwright 运行时代码和第三方许可证，不包含测试缓存、凭据和私有源码。
- 从 VSIX 解包目录解析运行时并实际启动 Chromium；使用隔离用户目录加载该插件，要求宿主写入本次运行 ID 对应的完成标记。解包烟测不替代从 VSIX 安装的人工验收。

执行 `npm run release:verify` 运行本地交付门禁，另以 `VSCODE_TEST_VERSION=stable` 执行 `npm run test:package` 验证目标稳定版。Linux 无桌面环境需通过 Xvfb 运行宿主。CI 在 Windows/Linux 的最低与稳定版检查后才上传通过包内门禁的 VSIX；未实际运行的 CI 不得标注通过。

## 真实账号与交互验收（不能用固定响应替代）

- [ ] 在干净 VS Code 环境中从 VSIX 安装，侧栏和命令正常出现。
- [ ] 使用有效 Copilot 账号选择模型、批准授权，完成一次真实源码分析。
- [ ] 验证无模型、拒绝授权、额度不足、模型无效 JSON 和中途取消路径；没有未经确认的源码修改。
- [ ] 如果要宣传 Codex 支持，先确认目标版本确实向 `vscode.lm` 注册模型并完成实际调用；否则只宣传 Copilot/兼容提供方。
- [ ] 选择实际组件与样式，审查每个 diff；确认应用、保存、运行现有测试并查看报告。
- [ ] 在授权的本地/预发布页面完成修复前后扫描；确认开发服务器确实加载了修复后的文件。
- [ ] 修复后额外手动编辑文件，再尝试撤销，应拒绝覆盖用户修改。
- [ ] 手动用键盘完整操作插件界面，使用 Narrator/NVDA/VoiceOver 检查名称、状态播报、焦点可见性与高对比度主题。
- [ ] 在组织常用的 Windows/macOS/Linux、远程 SSH/WSL 场景验证浏览器安装和来源策略；未测试的平台不宣称已验证。
- [ ] 审查源码发送范围、报告保留、任务授权和工作区信任要求，完成组织安全审批。

## Marketplace 发布

1. 由维护者确认并创建自己的 Publisher，核对扩展清单的 publisher、版本、许可、仓库地址与隐私说明；当前名称不代表已注册。
2. 在隔离测试环境验证交付 VSIX，保留版本号、提交号与包 SHA-256 校验值。
3. 用维护者自己的发布流程上传；凭据只在本地安全终端或 CI Secret 中配置，不发送给 AI。
4. 先进行小范围试点，记录模型兼容性、真实任务失败率及人工验收结果，再决定扩大范围。

## 回退

源码修复可用会话内“撤销最近修复”（仅内容一致时可用），或使用经审查的 Git 变更回退。插件版本可从已保存的上一版 VSIX 重新安装；不要通过自动 Git reset 撤销用户工作。
